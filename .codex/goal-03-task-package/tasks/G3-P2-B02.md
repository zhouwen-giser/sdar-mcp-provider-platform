# G3-P2-B02 — Repair RuntimeDeployment state convergence

## Phase

`P2`

## Dependencies

G3-P2-B01

## Objective

修复 RuntimeDeployment Reconciler 在 ACTIVE、DEGRADED 和 DISCOVERING 状态下不收敛的问题，并通过状态机回归锁定行为。

## Required Work

1. Add ADR defining health/identity/catalog convergence for HEALTH_CHECKING, ACTIVE, DEGRADED and DISCOVERING.
2. Implement at least:
   - ACTIVE + process not online/live/ready -> DEGRADED;
   - ACTIVE + healthy -> no-op ACTIVE;
   - DEGRADED + still unhealthy -> idempotent DEGRADED;
   - DEGRADED + healthy and identity valid -> DISCOVERING;
   - HEALTH_CHECKING + healthy and identity valid -> DISCOVERING;
   - identity mismatch -> existing fail path;
   - CatalogRegistry decorator closes DISCOVERING to ACTIVE only after both publications commit.
3. Production-oriented constructors/factories must not silently skip Provider Identity verification; if optionality is retained for isolated tests, name it explicitly as test-only/non-production.
4. Preserve revision fencing and idempotency.
5. Add deterministic transition, failure and retry tests, including concurrent stale revisions.
6. Do not implement periodic scheduling or production Worker wiring.

## Acceptance Criteria

- ACTIVE failure transitions to DEGRADED.
- DEGRADED recovery transitions through DISCOVERING and publication to ACTIVE.
- Healthy ACTIVE is idempotent.
- Failed Catalog/Registry publication never yields ACTIVE.
- Identity mismatch never yields ACTIVE.
- Revision conflicts are deterministic and tested.
- No scheduler, PM2 or production Worker composition is added.

## Evidence

Evidence includes a transition matrix, focused test names/counts and revision-conflict results.
