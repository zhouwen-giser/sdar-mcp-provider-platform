# G3-P1-B01 — Restore Docker workspace build and compose health

## Phase

`P1`

## Dependencies

G3-P0-B01

## Objective

修复干净 Docker Build 中的 Workspace Manifest/依赖安装问题，使基础 Runtime Compose 恢复绿色。

## Allowed Paths

```text
Dockerfile
scripts/verify-docker-workspace-manifests.mjs
tests/tooling/docker-workspace-manifests.test.*
docker-compose.yml (only if baseline proves a compose-only defect)
.codex/goal-03/**
```

## Forbidden Paths / Actions

```text
Application business logic
Runtime/Provider protocol
Migrations
PMS Worker/PM2 production code
.github/workflows/** (unless only correcting the exact build target name proven wrong)
Release files
```

## Required Work

1. Use B01 evidence to confirm the actual Docker Build root cause.
2. Audit `pnpm-workspace.yaml` and all workspace `package.json` files used by root `pnpm build`.
3. Ensure every required manifest is present before `pnpm install --frozen-lockfile` in the Docker build stage.
4. Add a deterministic verifier that fails when a workspace participating in the root build is absent from Docker pre-install staging.
5. Preserve layer caching and the existing runtime image security boundary (`USER node`, fixed entrypoint).
6. Do not add PMS image targets in this task.
7. Rebuild and start the existing runtime/adapter Compose path from a clean cache where feasible.

## Mandatory Verification

```bash
node scripts/verify-docker-workspace-manifests.mjs
docker compose config -q
docker compose build --no-cache runtime adapter-typescript
docker compose up --detach --wait --wait-timeout 120
curl --fail --silent --show-error http://127.0.0.1:8080/health/ready
docker compose down --volumes
pnpm typecheck
pnpm lint
git diff --check
```

## Acceptance Criteria

- Clean Docker build succeeds without host node_modules.
- Runtime and TypeScript Adapter images build.
- Base Compose reaches Runtime ready.
- Manifest verifier detects a deliberately omitted required workspace in its test.
- No PMS/PM2 production capability is added.
- No protocol or migration files changed.

## Evidence

Evidence includes exact original error, fixed build output, image targets, readiness response, and cleanup result.
