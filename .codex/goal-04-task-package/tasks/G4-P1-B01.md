# G4-P1-B01 — Pin PM2 and implement production JavaScript API bridge

## Phase

`P1`

## Dependencies

G4-P0-B01

## Objective

将 PM2 从测试环境中的临时 CLI 工具变成仓库固定、可注入、可关闭的生产 JavaScript API Adapter，保持既有安全边界。

## Allowed Paths

```text
packages/pm2-runtime-adapter/package.json
packages/pm2-runtime-adapter/src/pm2/**
packages/pm2-runtime-adapter/src/index.ts
packages/pm2-runtime-adapter/test/pm2-javascript-api.test.ts
packages/pm2-runtime-adapter/test/process-manager.test.ts
pnpm-lock.yaml
docs/adr/0009-pm2-javascript-api-binding.md
.codex/goal-04/**
```

## Forbidden Paths / Actions

```text
PMS Worker bootstrap/composition
Real PM2 E2E script
Runtime lifecycle semantics outside PM2 bridge
Migrations
Shell/exec/command APIs
Arbitrary process namespaces
```

## Required Work

1. Pin exact dependency `pm2: 7.0.3` in `@sdar/pm2-runtime-adapter` and update lockfile.
2. Add `createPm2JavascriptApi()` implementing the existing `Pm2JavascriptApi` contract using the installed PM2 module.
3. Support only connect, disconnect, start, stop, restart, delete, describe and list operations required by `Pm2ProcessManager`.
4. Normalize callback errors into stable adapter errors without leaking daemon paths, environment or command details.
5. Ensure `disconnect()` is invoked in all success/failure paths and repeated close is safe.
6. Keep namespace, release root, fixed runtime entry and environment allowlists in existing production classes; the bridge must not add a bypass.
7. Add focused tests for callback adaptation, connection failure, operation failure, disconnect cleanup and PM2_HOME isolation.
8. Add ADR explaining why CLI and `pnpm dlx` are not production authorities.

```bash
pnpm typecheck

python3 .codex/goal-04-task-package/scripts/verify_pm2_product_path.py . --bridge-only
git diff --check
```

## Acceptance Criteria

- PM2 7.0.3 is present as an exact dependency and lockfile entry.
- Production bridge uses the JavaScript API, not shell or CLI.
- Existing process namespace and release restrictions remain active.
- Connection/disconnection behavior is deterministic and tested.
- No Worker or E2E code is changed.
