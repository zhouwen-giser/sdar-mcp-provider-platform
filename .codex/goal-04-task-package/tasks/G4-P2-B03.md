## Required Work

1. Add a single production Worker Composition Root that constructs:
   - PMS Pool and migrations;
   - Provider Package Sync;
   - Runtime deployment/process/database-profile repositories;
   - Postgres Provisioner and provisioning credential resolver;
   - Runtime Migration Runner;
   - File Secret Store;
   - Runtime Release Resolver;
   - Bootstrap Config Renderer;
   - production PM2 JavaScript API and Process Manager;
   - Runtime Lifecycle Manager and Health Probe;
   - Runtime Database Preparation Service;
   - RuntimeDeployment Reconciler;
   - Provider Identity verifier;
   - Catalog/Registry publication phase and reconcile decorator;
   - Periodic Reconcile Scheduler.
2. Job Registry must contain exactly:
   - `provider_package.sync`;
   - `runtime_deployment.reconcile`.
3. `createRuntimeDatabasePreparationJobHandler` must not be registered; remove/deprecate it if Goal 03 did not already do so.
4. The Reconcile Handler must call the decorated production Reconciler, so DISCOVERING can become ACTIVE only after Catalog and Registry commit.
5. Start order: migrations/config validation → composition → scheduler → worker loop.
6. Shutdown order: stop scheduler → stop claiming new work → wait current handler or bounded timeout → disconnect PM2 API → close Pool. Do not stop/delete running Runtime.
7. Partial construction failures close all created resources.
8. Package manifests must explicitly declare direct workspace dependencies.
9. Update operations documentation with exact environment and failure behavior.

## Acceptance Criteria

- Production bootstrap no longer registers only Package Sync.
- Exactly two external Job Types are registered.
- All lifecycle components are reachable from one Composition Root.
- Production Reconciler includes Identity and Catalog/Registry closure.
- Shutdown leaves running Runtime untouched.
- Construction failure and repeated close do not leak Pool, timers or PM2 connections.
