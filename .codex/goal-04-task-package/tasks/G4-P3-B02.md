# G4-P3-B02 — Add final platform CI qualification jobs

## Phase

`P3`

## Dependencies

G4-P3-B01

## Objective

把 Runtime、PMS API、Worker/PM2、Provider 和平台 E2E 变成独立、可诊断、必须通过的 GitHub Actions Jobs，并保留所有历史门禁。

## Allowed Paths

```text
.github/workflows/**
package.json
scripts/**
reports/ci/**
docs/review/GOAL04_CI_MATRIX.md
.codex/goal-04/**
```

只允许为 CI 可重复性修复测试启动脚本；不得修改业务语义。

## Forbidden Paths / Actions

```text
Removing verify:v2 or verify:platform steps
Skipping tests by environment
|| true / continue-on-error for required work
Downgrading assertions
Publishing secrets or full PM2 dumps
Changing product behavior
```

## Required Work

1. Preserve existing `runtime-ci` and `runtime-compose` Jobs from Goal 03.
2. Add or finalize separate Jobs:
   - `static` — frozen install, format, lint, typecheck, build, protocol, SBOM;
   - `pms-api-production` — production API, PMS config and migrations;
   - `worker-pm2-production` — full Goal 04 lifecycle gate with isolated PM2_HOME;
   - `provider-regression` — UGV, NPC Tank and Home Assistant controlled regressions;
   - `platform-e2e` — security, fault injection, Catalog/Registry and controlled SDAR;
   - retain `runtime-regression` / `verify:v2` without weakening it.
3. Use Node 22, pnpm 11.13.1, PostgreSQL 17 and repository-pinned PM2.
4. Give each PostgreSQL-heavy Job isolated database/schema/ports where needed.
5. Upload redacted summaries, not credentials, database URLs, PM2 dumps or full temporary directories.
6. Set explicit timeouts and always-run cleanup.
7. Add a CI matrix document mapping each merge criterion to a Job and command.
8. Run workflows locally where possible and inspect actual PR checks; fix only reproducibility defects.
9. Branch-protection Required Check configuration is an external repository setting: record exact required Job names for the human/admin action, but do not mark the code task blocked if the API permission is unavailable.

## Mandatory Verification

```bash
pnpm install --frozen-lockfile
TEST_DATABASE_URL=<local-postgres> pnpm verify:v2
TEST_DATABASE_URL=<local-postgres> pnpm verify:platform
TEST_DATABASE_URL=<local-postgres> pnpm test:worker-pm2-production
TEST_DATABASE_URL=<local-postgres> pnpm test:pms-api-production
TEST_DATABASE_URL=<local-postgres> pnpm test:provider-platform-ugv
TEST_DATABASE_URL=<local-postgres> pnpm test:provider-platform-npc
TEST_DATABASE_URL=<local-postgres> pnpm test:provider-platform-ha
pnpm typecheck
pnpm lint
pnpm format:check
git diff --check
```

Use the repository's environment requirements for Provider commands; do not remove their fail-closed guards.

## Acceptance Criteria

- All final qualification areas have distinct CI Jobs.
- Existing Runtime/Compose gates remain present.
- No required Job uses `continue-on-error` or weak success shims.
- Worker/PM2 production gate runs the real product path.
- CI logs/artifacts are redacted and cleanup always runs.
- Required Check names are documented for branch protection.
