# G4-P2-B02 — Add periodic reconcile scheduler with database-backed deduplication

## Phase

`P2`

## Dependencies

G4-P2-B01

## Objective

增加单节点周期性 RuntimeDeployment Scheduler，使用现有 PostgreSQL、Job Lease、数据库时间和事务互斥补齐 Reconcile Job，避免第二套调度系统和无限重复 Job。

## Required Work

1. Implement a scheduler that periodically identifies RuntimeDeployments requiring continued reconciliation, including running/draining REQUESTED through ACTIVE/DEGRADED states as defined by Goal 03 ADR.
2. Use PostgreSQL database time for candidate age and job availability.
3. Serialize scheduler ticks across processes using a transaction-scoped PostgreSQL advisory lock or equivalent existing database primitive; no new table is permitted.
4. Atomically enqueue `runtime_deployment.reconcile` only when the same Provider/Deployment has no pending or leased effective Reconcile Job.
5. Succeeded/failed historic jobs must not block future periodic Reconcile.
6. Preserve Job Lease fencing. Scheduler never executes lifecycle work directly.
7. Implement start, tick and idempotent stop; stop waits for the current tick but does not stop Runtime or Worker handlers.
8. Add backpressure: bounded batch, configured interval and no immediate busy loop.
9. Add tests for concurrent ticks, active job deduplication, historic jobs, worker restart recovery, database-time behavior and lock release on failure.
10. Do not add a second external Job Type.

## Acceptance Criteria

- Concurrent scheduler ticks create at most one effective pending/leased Job per Deployment.
- Historic completed/failed Jobs do not prevent future ticks.
- Database/advisory lock failure leaves no partial Job.
- Scheduler restart restores continued reconciliation.
- Only `runtime_deployment.reconcile` is emitted.
- No Migration or direct PM2/Runtime call is added.
