# 光电 ZMQ 接口（C++ / CARLA）

实现依据 `doc/zmq/光电ZMQ对接协议.md`，wire protocol 固定 `2.3`，设备默认 `isr-01`。
只注册 `AreaSearch`、`CircularSearch`、`TaskControl`、`TeleControl`，没有 `GetStatus`、旧方法别名、server_session 或有效期字段。
Command.state 仅 accepted/failed；遥控执行状态 telecontrol.state 独立使用 running/succeeded/failed。

## 构建与启动

```bash
cd ros_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select actor_control actor_spawn ros2_zmq_server_sl
source install/setup.bash
ros2 launch ros2_zmq_server_sl eo.launch.xml
```

先按现有仿真流程启动 UGV、`gimbal_updater`、`spawn_gimbal_camera` 和 `/ugv/kinematics` 数据源，再启动光电节点。
节点启动先发零速度、撤销遗留跟踪，并通过新鲜实际姿态验证停稳；超过 3000ms 仍不能确认会锁定故障，需要排查反馈后重新启动节点。
`eo.launch.xml` 仅启动光电 ZMQ 节点；`chassis.launch.xml` 仅启动底盘 ZMQ 节点，两者可同时运行。

REP bind `tcp://0.0.0.0:5555`，PUB bind `tcp://0.0.0.0:5556`。SUB 订阅 `isr/isr-01/`，消息严格为 topic + JSON 两帧。
部署参数见 `config/eo.yaml`，可用 `ros2 launch ... eo.launch.xml config:=/absolute/path/eo.yaml` 替换。
`nlohmann_json` 为 JSON 解析依赖，`libzmq` 沿用该包现有依赖。

## 对象与文件职责

| 文件 | 职责 |
|---|---|
| `eo/protocol.hpp`, `src/eo/protocol.cpp` | 严格 JSON 信封、方法参数、ID、有限数值、凸四边形验证、回执 |
| `eo/scan_plan.hpp`, `src/eo/scan_plan.cpp` | 四点区域几何、水平面规划、导航角度解算、连续周扫/扇扫路径 |
| `eo/controller.hpp`, `src/eo/controller.cpp` | 单任务所有权、幂等账本、扫描执行、暂停恢复、单调预算、停止监督、遥控 |
| `src/eo/observations.cpp` | 同帧识别转换、像素/框校验、按置信度截断、单目标选择及跟踪事件 |
| `eo/ros_hardware.hpp`, `src/eo/ros_hardware.cpp` | ROS 发布/订阅、异步锁定服务、FLU rad 与仿真 degree/right-positive 转换 |
| `eo/transport.hpp`, `src/eo/transport.cpp` | REP/PUB socket 生命周期、单帧请求、multipart 拒绝与完整消费、字节上限 |
| `src/eo/main.cpp` | 节点组装、10ms 调度、周期与即时发布；所有 socket 仅由该执行器线程使用 |

不启动额外线程访问 socket；ROS 服务调用异步完成，不让 REP 等待物理动作。
任务 ID 内部使用本次进程的随机标识和递增计数，避免重启复用；随机标识不是对外会话字段。
本次进程内最多保存 8192 个命令请求/原回执；满后返回 RESOURCE_EXHAUSTED，不淘汰记录后重新执行旧请求。重启不保留幂等账本。

## ROS 接口与执行端

| 方向 | 接口 | 内容 |
|---|---|---|
| 发布 | `/eo/leased_motion` Float64MultiArray | 内部指令 `[mode, yaw_deg, pitch_deg, speed_deg_s, lease_ms]`；mode=0 时中间两项是有符号角速度，mode=1 是绝对角度；租期至多 300ms |
| 订阅 | `/current_pose` Float64MultiArray | 使用前两项实际角度，实际角速度由连续样本差分得出；不把后两项配置速度当成实测速度 |
| 发布 | `/eo/observation_task` String | 当前观测任务 ID，空串撤销；100ms 心跳 |
| 订阅 | `/eo/observations` String | 同一次曝光的 task_id、图像编号/尺寸、像素检测框与锁定标记 |
| 订阅 | `/eo/tracking_pose` String | 同帧跟踪器提出的目标角；核对原任务/目标、状态、预算和新鲜反馈后才下发，迟到建议不能驱动新任务 |
| 订阅 | `/eo/executor_fault` String | 本地云台校验拒绝或机械限位异常，锁定 DEVICE_FAULT |
| 订阅 | `/ugv/kinematics` VehicleKinematics | CARLA 世界位置、姿态和 GNSS 有效标记；只接纳近水平车体导航 |
| 发布 | `/eo/task_status` String | 内部只读可视化快照：task、command、region；区域为世界坐标四顶点，type=5。周期 1Hz 与任务状态变化时发布；终态/无区域任务 region=null，不改变 ZMQ 协议 |
| 发布 | `/eo/targetlist`、`/eo/tracklist` String | 与对应 ZMQ 事件 data 相同的只读副本，Dashboard 按任务 ID 关联两类列表，显示类别/像素/跟踪状态和可用定位；空帧替换旧结果，超过 2 秒未更新不作为当前结果显示 |
| 客户端 | `/ugv/target_lock` TargetLock | 使用 actor ID 精确选择仿真对象；停稳确认还需解锁回执，不能仅凭发送成功 |

Dashboard 订阅 `/eo/task_status` 显示 UGV ZMQ 区域任务；快照包含 device_id，暂停保留区域，终态或超过 3 秒未收到快照时清除，不产生覆盖率。暂停/继续/终止按钮使用快照的设备及任务 ID，通过 ZMQ TaskControl 的 pause/resume/stop 控制；EO 指令地址可由 Dashboard 的 eo_command_address 参数指定（默认 tcp://127.0.0.1:5555）。该路径不向 `/area_recon/cmd` 发命令，回执只表示接纳，按钮状态以任务反馈为准。

面板绘制的 UGV 四边形通过 AreaSearch 配置（携带所选 recognize/track 策略，预算 120 秒），使用返回 task_id 再 start；启动失败时尝试停止该任务，不回退旧扫描控制。其他载体或区域形状保留原 ROS 侦察方式，不新增自动跟踪能力。四边形任务不单独接收界面的扫描次数/速度设置。

为兑现断联停止和同帧上报，执行端增加了必要的配套改动：

- 公共 V2 EO 控制链管理租期、机械限位和位置运动；停止或换模式时先撤销旧运动。
- `actor_spawn/utils/eo_exposure.py`：保存最近 64 帧 WorldSnapshot 与最近 64 次任务切换边界。检测采用 image.frame 对应的 actor pose 和 image.transform；没有对应快照时不发布该帧，不能用现在的 actor 位置补充旧图像。
- `spawn_gimbal_camera.py`：生成跨重启唯一图像编号；按曝光帧关联原任务；使用同帧检测框生成观测。EO 跟踪固定选中的 actor，跟踪器只提出目标角，由 C++ 控制器准入后统一写入带租期的入口；失去任务心跳撤销跟踪。EO 任务期间暂停自动变焦，避免成像内参在扫描中变化。

observed_at_utc_ms 使用同帧 WorldSnapshot.timestamp.platform_timestamp：首帧 tick 回调以本机 UTC 建锚，后续按 CARLA 平台时钟差换算并随帧保存；不使用仿真 elapsed_seconds（其速率可能不同于墙钟），不以处理/发布时间替代。此为仿真 UTC 估计，包含首帧传输延迟，非硬件授时；场景帧号回退时重建映射，缺少有效平台时间时为 null。TargetList 与 TrackList 保留同次观测时间；acquiring 使用触发帧时间，无帧的 lost/idle 通知为 null。published_at_utc_ms 在构建上报消息时使用 EO 主机系统 UTC。
默认 sensor_tick=0.1s，目标结果随有效帧最多约 10Hz。DeviceStatus/TaskStatus 固定 1Hz，全量快照；关键状态改变另发即时事件。

## 已支持的能力与部署边界

- 区域任务先校验、规划，再 ready，不运动；start 才执行。四点必须沿边界严格凸、处于配置水平面、在当前机位距离/机械仰角范围内。按配置间距在凸区域内生成蛇形观测点（至多 4096 点），移动平台的目标角度使用新鲜导航重新解算。
- 区域扫描完成表示计划观测点已走完。未接入经过曝光/视场/遮挡认证的面积覆盖模型，progress_ratio、coverage_ratio、coverage_complete 均为 null；不以格点比例冒充面积覆盖。当前适用于部署约定的无额外地形遮挡水平面，不能承诺任意场景的全覆盖。
- 周扫沿正 yaw 方向执行完整 2π；扇扫从负边界向正边界再返回，每个往返为一圈。内部使用至多 π/4 的连续相邻角段跨过 ±π；按实际姿态记录扫描路径和循环，暂停恢复不清零预算/进度。位置段之间有停稳观测时间，不能按角宽/速度直接推算完成时间。
- 当前适配器面向连续 yaw 的仿真云台；continuous_yaw=false 时拒绝 CircularSearch。其他硬件需要提供自己的实际 yaw 限位和连续运动适配，不能直接套用仿真配置。
- 位置遥控与有符号速度遥控支持；速度更新只允许替换当前速度动作。重复 request_id 不续租。速度租期由执行端监督，暂停、完成、终止均需连续实际停稳样本和解锁回执，3000ms 未确认进入 STOP_UNCONFIRMED 并继续监督。故障锁定后不接纳新运动。
- 仿真相机重建/FOV 变化不是具有镜头完成反馈的光学变焦，因此 zoom 返回 UNSUPPORTED，zoom_ratio=null。真实镜头接入后才能宣告支持。
- track 策略按 confidence 降序、target_id 升序选择一个目标，锁定期间保持初始 target_id；丢失后重新搜索。无帧时不重复旧坐标，acquiring/lost 按 1Hz 报状态，暂停/终止发 idle。
- `next_follow` 的允许状态、无候选及轮换完成规则尚未定稿，本次不注册该动作；请求会明确拒绝。
- 当前检测是 CARLA 包围盒投影的仿真结果，data_origin=simulated、confidence=1.0；没有威胁度评估，threat_level=null。TrackList 使用同次曝光的 CARLA 目标 actor 原点作为仿真参考点，由光心至该点的三维欧氏距离得到 range_m，经机场统一 GNSS 转换得到 position，并使用该点的图像投影作为 pixel；range_source=simulated_radial_depth、reason=null。这不是实测激光或表面回波。缺少曝光快照/参考点在画外时返回 NO_RANGE，输入定位几何无效时返回 INVALID_GEOMETRY；不复用旧位置。
- TrackList 的有效条目额外包含 image（与 pixel 对应的相机/图像编号及尺寸），补足协议“同帧像素”要求；协议中已同步明确该字段。
- 当前请求信封没有调用方身份或鉴权字段，无法实现按外部用户区分的任务所有者。接口用于单一受信控制方；不能把设备 ID 检查当成多用户权限控制。原有 MCP/区域扫描节点不得同时写同一云台；当前所有权覆盖此光电节点内部请求。
- 默认仿真标定：相机相对平台高度 4m、无额外 yaw 偏置，俯仰 -85°～10°，速度上限 30°/s。修改时须同时对齐 eo.yaml、gimbal_updater 的 EO 速度/俯仰限位与 spawn_gimbal_camera 的 EO 俯仰限位参数；实际相机安装、导航原点和平面高度也必须一致。

### 仿真重置与反馈故障恢复

- EO 订阅 `/simulation/reset` 的 `ugv/all`，明确终止旧任务（`failed/SIMULATION_RESET`）、停止并解锁，等待新相机/姿态后恢复接单；不会自动恢复旧扫描。相机销毁至重挂载期间无帧是预期行为，仍以 500ms 判定 camera_online，不伪造帧或延长新鲜度。
- 冷启动与仿真重置先等待新鲜相机和姿态反馈，期间不接纳新运动；readiness 的 `awaiting_feedback=true`、`stop_elapsed_ms=null` 表示设备尚未上线。两类反馈到齐后才启动 3000ms 停稳确认期限，仍要求连续低角速度样本与实际解锁回执；部署等待时间不计为停止失败。运行中的停止、暂停、完成仍立即开始原有停止监督，既有锁存故障不会被仿真重置清除。
- 活动任务/遥控中相机或姿态超时仍立即停止并失败（`DEVICE_FAULT`）。仅此类反馈中断可在停止确认、新鲜相机/姿态、解锁连续满足部署 settle_ms 且取得新的相机/姿态样本后自动解除设备故障；旧任务失败结果保留。
- 执行器主动上报故障、内部异常和 `STOP_UNCONFIRMED` 继续锁定，不凭新相机帧自动清除。readiness 中 `fault_recoverable` 和 `recovery_elapsed_ms` 显示恢复类型/等待时间，NOT_READY 文本明确实际故障。

### 周扫/扇扫无限模式与进度

- `cycle_count=0` 为无限循环，`task_timeout_ms=0` 为不设截止时间；正值约束独立生效，两项均为 0 时持续扫描。AreaSearch 同样接受 task_timeout_ms=0（无截止时间），但扫描完有限区域路线后仍正常结束，不循环该区域。
- 有限周扫/扇扫配置后 `progress_ratio=0`；从实际姿态累计扫描路径，分母为（周扫 2π 或扇扫 2×角宽）×循环数，到起点过程不计入，暂停/跟踪不以墙钟累加。coverage_ratio/coverage_complete 不适用，保持 null。
- 无限循环配置后进度为 0，首次 start 起固定 `progress_ratio=0.01`（1%），暂停、恢复及终态保留；completed_cycles 实际累加、total_cycles=0。无时间上限时 remaining_ms=0，不代表任务已经结束，须读 state。
## typed map扫描的可选指定实体

ZmqEoScanV2.target_entity_id为空时保留原自动选取，非空仅track策略可用；原Controller从当前曝光只锁定指定公共实体，缺失不改锁其它实体。对应params的可选target_entity_id纳入原request_id内容校验；旧客户端省略字段，新字段需要新服务端，旧native模式不支持。实体ID与不透明det/track ID不能混用。内部ROS扫描IDL已扩展，部署须配套重建消息、网关和调用方。

## V2.3 同帧像素接口

TrackList 的有效条目包含必填可空 `bbox`、`observed_at_utc_ms`。框来自同次观测；定位参考点像素落在半开框外时 `bbox=null`，保留原参考点像素及定位，不扩大框或改用框中心。逐目标时间始终等于 data 级曝光时间。公共 `EoObservationV2` 未提供可靠 UTC 映射，V2 路径这两处时间及帧头/取帧的 `exposure_utc_ms` 均为 null。

`use_v2=true` 的受保护 UGV/Tank 组合新增：

- 从 `/<entity_id>/eo_camera/frame_v2` 的原始 `CameraFrameV2.image` 接收 BGR8 像素，校验 epoch、公共实体、相机、光学帧、曝光新鲜度和尺寸。图像缓存、检测和跟踪共用网关实例+epoch+曝光纳秒生成的 frame_id；网关重启不复用编号。原图尺寸和坐标不变，不使用处理器 HUD 输出截图。
- 每个接纳的公共原图先入缓存，再经现有 PUB 发布 `isr/<device_id>/frame_header`（topic+JSON 两帧）。没有新图像不补发帧头。现有公共 ROS 相机流是本实现的视频通道；没有新增 RTSP/H.264/RTP 或伪造 RTP 时间戳。接入压缩视频输出时仍需在实际发送端建立映射，不能直接把此处帧头当成任意视频的映射。
- FramePull 独立 REP，默认 **`tcp://0.0.0.0:5559`**，避开本仓火炮默认 5557。参数 `frame_pull_address` 可更改，远程客户端连接服务器实际 IP。仅接收协议第 5.5 节的 `camera_id+frame_id`，成功 JSON+JPEG 两帧，失败仅 JSON。相机 `eo` 无缓存帧返回 FRAME_UNAVAILABLE，未知相机返回 NOT_FOUND；时间查询和额外字段拒绝。重试重新查询当前缓存，不进入任务账本。
- JPEG 固定质量 90、原尺寸，16 MiB 上限，超限 RESOURCE_EXHAUSTED；不缩图、不换帧、不生成占位图。缓存、编码、发送使用有效共享引用防止淘汰竞态；编码与辅助 REP 在独立工作线程，不访问任务 socket 或写控入口，主线程继续监督任务和租期。
- 原图缓存目标窗口 5 秒，最多 4096 帧，总像素预算由启动只读参数 `frame_cache_mib` 指定，默认 512 MiB；超时帧不再可查，资源压力提前淘汰时明确记录容量不足。预算约束缓存像素，另有一个在途查询持有的原图、JPEG 编码工作区和 ROS 队列开销，部署需额外预留内存。以 BGR8 计算：1280×720@10fps 的 5 秒约 132 MiB，1920×1080@30fps 约 890 MiB，后者默认预算不足，不能声称满足 5 秒。相机分辨率和帧率以实际部署为准。
- 仿真 epoch 切换清空缓存；旧 frame_id 不会指向新场景图像。无有效源像素时不发布帧头；旧版 `use_v2=false` 只有观测元数据，不启动辅助像素服务。

显式启动例子（其他必需地图参数沿用原部署）：

```bash
ros2 launch ros2_zmq_server_sl eo_v2.launch.py \
  entity_id:=ugv entity_type:=ugv \
  map_latitude:=29.7195 map_longitude:=106.81485 map_altitude:=500 \
  frame_pull_address:=tcp://127.0.0.1:5559 frame_cache_mib:=512
```
