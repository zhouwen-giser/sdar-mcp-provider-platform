# Known limitations

The joint run is intentionally closed as `UGV_SMPP_TELEMETRY_JOINT_PARTIAL`. It is not a qualified live-control run.

The final deployed SMPP revision for these observations is `eaa36df380e7542f25f359d55c829e12d843738b`; both Runtime and Adapter image revision labels match it. The read-only smoke at that revision exited successfully, while mission state remained `4`, so the strict G3 limitation below is unchanged.

1. The live Device MCP server reported protocol `2025-11-25`; the task contract requires `2026-07-28`. All 15 tools were discoverable, including the two point-navigation primitives, but none declared `outputSchema` or annotations. Runtime-side strict result validation therefore remains mandatory.
2. The simulator did not publish canonical `status/ugv` during the bounded passive capture. The compatibility alias `/ugv/status` was active at about 5 Hz. `/ugv/speed` was published with QoS 0 rather than the required QoS 1. The Provider now applies explicit canonical-first authority and timed alias handoff, but code-side tolerance does not qualify the upstream contract.
3. The current state was read successfully through Runtime, but the retained evidence shows chassis mission state `4` rather than the strict pre-dispatch value `0`. The availability check returned `available`, but the redacted current-run evidence does not prove speed equals zero, position is parseable, every required freshness domain is neither stale nor unknown, execution mode is live, or mock fallback is false. G3 and `LIVE_READ_READY` therefore remain partial; no mutation was authorized from the availability result.
4. `ALLOW_LIVE_UGV_CONTROL`, `ALLOW_LIVE_POINT_NAVIGATION`, task-control, emergency-stop, and fire gates remained disabled. No navigation idempotency key was generated, no Runtime Task or Provider Execution was created, and point navigation, pause, resume, cancel, emergency stop, and fire call counts are all zero.
5. Runtime carried a historical durable ProviderOps FIFO backlog. An early non-atomic sample showed 821,689 records and oldest age about 872,771 seconds; the latest non-atomic snapshot showed backlog 726,934 with `CLAIMED=44`, `PENDING=127413`, `RETRY_WAIT=599514`, `DELIVERED=136156`, `EXHAUSTED=166347`, and oldest age 874,895 seconds. The decrease does not constitute drain-to-zero, and the separately sampled gauge and state counts are not asserted to sum exactly. Telemetry's latest 134,864/134,864 unique watermark is landing-only (`max occurredAt=10:45:55.689Z`, `max ingestedAt=15:07:40.656Z`); final Runtime epoch rows remain zero, so current-run normalized/core/query convergence is not proven.
6. Resource-level correlation is proven for provider, resource, Runtime instance, deployment, record ID, and record hash. Task ID, external execution ID, operation name, mission ID, and task-level ProviderOps are absent because no live task was created.
7. The first final-revision Adapter/Runtime order switch produced explicit Provider Telemetry transport failures, bounded retries, and 4 retry-exhausted drops before ingress resumed. These were observable rather than silent, but the lost resource events were not reconstructed. A later isolated Adapter force-recreate while Runtime stayed healthy produced 61/61 unique resource events with complete state/metric payloads and zero rejected, transport-failed, or dropped log entries in the 20-second window.
8. The isolated Provider restart qualifies only telemetry recovery without an active Execution. It does not prove active mission recovery, mutation-journal recovery, or no redispatch. Controlled live fault injection was not performed for Collector, Processor, ClickHouse, Runtime ingress, Runtime restart with a task, MQTT disconnect, or Device MCP disconnect. WAL duplicate/conflict, checkpoint, poison/drain, and active-task no-redispatch behavior remain code-level evidence; overall recovery convergence is not claimed.
9. The fresh 15-second MQTT rate capture deliberately retained no raw payload or fresh payload hashes. A bounded hash/shape index from the same simulator captured on 2026-08-10 is included only as supporting evidence and is not represented as the current rate window. No source sequence was observed, frame IDs were empty, and the observed run ID was zero.
10. The stack is a development profile using permitted cleartext internal transport. mTLS, production certificates, production RBAC, high availability, and production-scale load testing are outside this task.

Scope remained bounded to the task paths. The SMPP development override is under `deploy/development/ugv-runtime-telemetry-joint/`; Telemetry's x86 development override is under its allowed `deploy/development/` path. Telemetry does not connect directly to MQTT, Device MCP, or Runtime/Provider databases.
