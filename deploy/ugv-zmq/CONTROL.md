# ZMQ 基础任务闭环（第三阶段）

实现：`packages/vehicle-zmq-control`。本阶段交付可执行的隔离控制引擎及真实 PostgreSQL、原生 ZMQ 联调夹具。19100/19101 的目录、后端和 Docker 配置没有切换。正式 MCP 装配、TaskBusiness 结果、面板入口、SDAR 绑定及发布仍按第四、第五阶段推进。

## 可验证的动作

| 操作                                | 本阶段处理                                                                                       |
| ----------------------------------- | ------------------------------------------------------------------------------------------------ |
| `navigation.point/route/returnHome` | 新模式接收门槛、速度/避障设置、任务配置、规划反馈、一次 START；运行/暂停/恢复/结束与终态物理证据 |
| `camera.position/zoom/velocity`     | 绝对位置、绝对倍率、有限速度租期；回执与动作结果分离，完成位置/倍率与反馈交叉核对；只支持终止    |
| `recon.area/circular`               | 区域/扇扫的配置、原生字符串任务号、ready 后一次 start、暂停/恢复/取消；成果完整性留至第四阶段    |

区域仍按光电 2.2 的四点严格凸 WGS84 边界和显式椭球高输入。没有二维任意多边形到四点区域的静默转换。没有方位距离导航、相对云台、指定对象跟踪或独立测距的伪实现。

`ControlSettings.mode` 只接受 `isolated_simulator`；六个 endpoint 均须为数字 `127.0.0.1`。提供方 192.168.2.63 的候选配置会被拒绝发送。测试使用明确标注的模拟 Provider、资源、场景、来源绑定、限值及发送端 ID。生产控制端 ID 省略时保持 null，导航拒绝发送二进制命令；不会推导设备 ID 或默填线路发送值。

## 持久状态与控制

`StartControl` 固定 taskId、commandId、资源、授权域、simulationId、操作参数及计划时间。查询和生命周期控制核对执行身份；同 ID 同内容返回原记录，同 ID 异内容拒绝。不同组件同时操作也检查 ID 冲突。

复用 `ugv_execution.payload.zmqControl` 及 `ugv_mutation_journal`；原有迁移不修改，不新增业务表。执行绑定完整 profile/合同/设置摘要，包含端点所有权键、原生任务号、准确请求帧、阶段、代次、期限、原始接收引用和占用。回执返回已提交的快照。监听器只接收已确认写入观测档案的记录。

`PostgresControlRepository` 当前用于隔离的独立 Provider 数据库，要求 `store.pool` 与租约池一致，不接入 GOWM 共享存储路由。第五阶段须完成正式存储装配/路由审查，不得直接连接当前联合部署数据库。构造仓库时配置有限的连接、查询和 SQL 超时；控制池与接收档案池分开。测试使用临时 PostgreSQL，数据库凭据经私有文件传入，不写入代码、证据或命令行。

每个命令端点分别持有 PostgreSQL advisory lock，发送前复核仍有效；部分端点重叠也拒绝第二发送者。相同端点存在其他 profile/场景的未结占用时禁止启动新发送者。数据库锁不能撤回在途消息，也不能让设备执行 fencing；不提供自动故障接管。

模式每次等待 3000ms，最多三次同值发送。任务配置、START、恢复和遥控不自动重试。每次 REQ 只做一次 send/receive，超时后关闭该 socket；下次控制新建 socket。通道连接、PUB 本地发送、REP accepted 和业务完成分别处理。

## 期限与停止

计划开始时间、启动容差、平台 maxElapsed 与父任务绝对期限独立保存。平台总预算从首次进入准备阶段起消耗，包含模式等待、准备、暂停、恢复及传输等待；每次发送前复核。设备任务预算取原请求与平台剩余时间的较小值；设备从首次 start 起计时不等于平台提供了独立的设备硬期限。

自驾和光电有各自的有限步骤队列。观测回显、任务运行等等待不持有队列；取消使旧代次的排队 start/resume 失效。停止只针对本执行占用的组件，不能作为全车急停：仿真效果服务的动作不属于本停止范围。观察到自驾控制归属冲突时保留未知，不发送无任务号的 END。

每次首次运动前预先持久保存一个稳定停止请求及意图。执行表写入阻塞时，可在独立复核租约仍有效后使用该预存请求一次，记录停止回执持久化未确认；存储恢复后补记其日志。重启时，只要存在预存停止请求就保守地认为它可能已使用，禁止自动重派运动。租约丢失时所有发送均停止。数据库或设备完全不可达时保留未确认，不能声称停止通道已完成现场验收。

光电停止需本任务终态及新鲜 idle/ready 快照；遥控停止需原停止请求 ID 对应 succeeded。导航需匹配任务终态和至少两个不同的零速度定位接收样本，窗口至少 100ms。它们仍是隔离仿真证据；自驾源时间及服务启动代次未经提供方确认。平台从停止派发尝试起监督 3000ms，超时保持物理停止未确认、占用不释放；这不是设备首次物理停止动作到停稳的实测结果。

停止超时后的迟到证据可释放独立占用并保留最新对账事实；原终态、原因和结果保持不变。关闭引擎仅停止本地收发，不宣称设备已经停止。正式部署前仍须按单写入者交接门槛完成空闲核实和未决动作对账。

## 恢复与证据限制

进入 DISPATCHING 或可能使用预存停止请求的执行在重启后标记未知并保留占用；不自动重派动作。已落库但尚未发送的意图在新鲜状态到达后可以继续，不重置期限。受理日志已保存的原生任务号可恢复查询身份；没有服务 boot/session 及持久请求查询保证时，不据此证明跨重启完成。

正在执行的来源通道断连或发生接收缺口时，同样保留未知；重连后的相同原生任务号及 completed 快照不能证明原任务完成，也不能授权停止新实例的动作。来源中断引用持久保存，取消入口保持对账阻塞，预存停止请求也不会跨越未知来源身份自动派发。

自驾规划反馈没有 mission/request ID，系统模式没有发布时间或来源代次。测试在声明的隔离单写入者条件下验证时序，结果继续列出 `CHASSIS_FEEDBACK_UNCORRELATED`、`MODE_PUBLICATION_ORDER_UNVERIFIED` 和来源启动身份缺口。光电没有可恢复的任务发现流，因此本阶段不产生完整检查报告或“全任务无发现”结论。

## 验证

```bash
pnpm test:ugv-zmq-control
SMPP_ZMQ_TEST_CONFIG_FILE=/private/isolated-postgres.json pnpm test:ugv-zmq-control:postgres
```

配置文件只有 `databaseUrl`，权限应为 0600，指向专用临时数据库。原生测试显式安装既有 Provider 024/027 SQL 和独立观测档案，不使用运行实例数据库。夹具位于 `tests/ugv-zmq-control-postgres/`：实际 PUB/SUB、REQ/REP、100Hz 计划定位输入、加速的 20Hz 状态快照；它不模拟真实设备物理学，也不是提供方服务实现的替代验收。

`SMPP_ZMQ_CONTROL_EVIDENCE_FILE` 可保存任务、发送计数与日志；`SMPP_ZMQ_CONTROL_RAW_EVIDENCE_FILE` 可保存关闭接收会话后的原始接收链。SIGKILL 用例覆盖意图保存前/后、发送前、发送后、原生身份保存前及终态保存前。报告见 `reports/ugv-zmq-phase3/REPORT.md`。

剩余现场门槛：G0 身份/时间/限值/提供方证据，自驾反馈关联，服务重启与持久请求查询，设备本地期限和停稳实测，GOWM/正式 MCP/TaskBusiness 装配，以及 G4–G6 的成果、目录、切换和回退验收。
