# Runtime Task business binding (`1.0-rc2` development)

`createRuntime` constructs `TaskBusinessGateway` from the existing `TaskRepository`, persisted `OperationSnapshotRepository`, validated Provider Manifest and private Adapter Gateway. `TaskBusinessPublicService` uses this binding for public reads and receives the existing Task Engine for conditional Intervention submission. The frozen handler recognizes `io.sdar/taskBusiness/context/get`, `io.sdar/taskBusiness/snapshotParts/get`, `io.sdar/taskBusiness/artifacts/get` and `io.sdar/taskBusiness/interventions/apply`. Discovery advertises methods according to the validated Operation Profiles and available Runtime services. Intervention requires `methods.interventionApply` and at least one declared Intervention type; snapshot parts require `methods.snapshotPartGet`.

For every request it calls `TaskRepository.getAuthorized(taskId, authorization)` and then loads that Task's recorded Operation Snapshot. The Task row supplies Provider, operation, authorization hash, execution mode, simulation ID, external Execution ID, argument hash and resource argument. The client may supply Execution ID, resource, mode or simulation ID for consistency checks; none can replace the stored binding. A missing Task or changed authorization keeps the existing `TASK_NOT_FOUND` behavior. Unbound Execution, absent business profile, missing durable source and disabled Input/Intervention capability fail closed.

The Gateway forwards reads with the stored binding to the private Adapter RPCs. Each Task checks its persisted Profile, including optional snapshot-part access. Public reads validate returned identity, schema and exact references; signed continuation and snapshot tokens pin the authorized Task, Context revision and public stream generation. Its error mapper carries a stable `reasonCode`, `profileVersion` and `schemaVersion` in JSON-RPC `error.data`, including unsupported extension and Adapter failures. See [public query and snapshot rules](UGV_TASK_BUSINESS_PUBLIC_QUERY.md).

For Intervention, `TaskBusinessPublicService.applyIntervention` resolves the authorized Task with Intervention access, checks the command's Execution ID against the stored binding and calls `TaskEngine.enqueueBusinessIntervention`. The existing durable Task command queue, sequence and dispatcher forward the private `ApplyIntervention` RPC. The public receipt has `businessApplied: false`: actual adoption must arrive later as committed Provider business facts.

RequiredInput responses use the existing frozen `tasks/update` path, durable Runtime UPDATE command and private `UpdateExecution`. A user-only response requires a responder verified from authenticated JWT or the configured trusted proxy; a payload's actor claim is insufficient. See [interaction wire and authorization](UGV_TASK_BUSINESS_INTERACTIONS.md).

The currently implemented UGV Operation Profiles set `inputUpdate: false` and `interventionApply: false`. Their private Intervention handler returns a terminal negative Ack without a device action. The generic Runtime paths and synthetic local tests do not establish a UGV recon decision handler, real mission replan/adoption, selected GOWM qualification or an actual SDAR integration.
