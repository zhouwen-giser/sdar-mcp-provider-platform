# Current UGV observation footprint

The UGV currently publishes gimbal yaw/pitch/zoom, recon scan pitch, camera fault and vehicle pose. The checked Device MCP tools and MQTT topics do not publish a current ground footprint, calibrated field of view, camera extrinsics or a versioned pose-to-ground model. The Provider cannot convert those angles into a trustworthy WGS84 or local ground polygon. The requested recon area and reported coverage statistics have different meanings and cannot stand in for the current field of view.

`FootprintBusinessProcessor` is an **unwired** inbound port for a verified direct footprint or a calibrated model result. Each fact must bind to a persisted recon mission and area revision, identify a source version/time, and carry a Polygon or MultiPolygon with either `OGC:CRS84` or an explicit local frame/unit/axis. `quality=observed` requires a device-reported source. `nominal` and `estimated` require a model version; local derived geometry also requires a transform version. It stores immutable `recon.current_footprint` revisions and updates `activeRefs.currentFootprint` only after a committed active fact. Identical source versions are idempotent, conflicting versions fail, and active updates inside 500 ms are aggregated. Paused, ended or camera-fault facts bypass that interval and create an unavailable invalidation revision, clearing the active ref while preserving prior geometry.

The port accepts only the Execution's latest downstream mission and facts at or after Task creation. A delayed prior mission footprint cannot replace current geometry.

Area binding uses the exact effective `recon.area` version: the original requested revision 1 until `activeRefs.reconEffectiveArea` points to a planned adopted version. A newer candidate Artifact alone does not change the footprint basis. A footprint fact for the candidate area is rejected until adoption; a valid older source fact retains its source time without moving `Context.updatedAt` backward. A circular scan has no requested area Artifact and uses initial area revision 1. This is a local source-fact guard, not evidence that the selected device reports a footprint or adopts area changes.

An adopted area transaction clears the prior `activeRefs.currentFootprint`; the old version remains readable as history. Only a new footprint fact bound to the adopted `areaRevision` can restore the active view. The common Memory/native PostgreSQL Store rejects a switch that leaves an old active footprint in Context.

No current production source invokes this processor, and the recon Profile keeps footprint mode disabled and qualification `not_supported`. `EXT-UGV-FOOTPRINT` lists the missing direct footprint or calibration contract. Component tests use synthetic geometry; they do not demonstrate actual camera visibility, occlusion, detected targets, simulation or SDAR integration.
